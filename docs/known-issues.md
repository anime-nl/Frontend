# Known issues

Bugs and gaps that were found while working on something else. Fix them in their own change, with a test, and move the entry to "Fixed" (or delete it).

Format: **title** (where): what is wrong. Mark anything not yet reproduced as _unverified_.

## Open

- **`typescript` cannot be bumped past 7.0.2 yet** (`package.json`): Dependabot's PR #2 bumps `typescript` from 5.9.3 to 7.0.2, but `bun run typecheck` then fails with `Error [ERR_PACKAGE_PATH_NOT_EXPORTED]: Package subpath './lib/tsc' is not defined by "exports"`. TypeScript 7 does not yet expose the stable programmatic API that `vue-tsc`/Vue's language tooling needs; confirmed as a known, currently unfixable limitation in [vuejs/language-tools#6124](https://github.com/vuejs/language-tools/issues/6124) and [#6156](https://github.com/vuejs/language-tools/issues/6156) (both closed `not_planned`), and by [Microsoft's own TypeScript 7 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/#typescript-and-embedded-languages), which says Vue projects "will need to continue using TypeScript 6.0 for now". There is no newer `vue-tsc` release to bump to (3.3.11, already installed, is latest and still fails). Revisit once `vue-language-tools` ships v4 with real TS 7 support (tracked in their alpha PR [#6170](https://github.com/vuejs/language-tools/pull/6170)); until then, leave PR #2 open or add an `ignore` rule for `typescript` major versions in `.github/dependabot.yml`.

- **Trustpilot score is hardcoded** (`app/utils/navigation.ts`, `badge: '4.0'`): it will go out of date. Tried replacing it with a live TrustBox widget, but it was reverted at the shop owner's request: the chosen template did not show the numeric score, it broke the navbar's centering, and Trustpilot's widget styling does not fit the site's theme (only height/width/theme/locale are customizable). A live score would need either a different, better-fitting TrustBox template plus a navbar layout that isolates it from the centered nav, or fetching the score server-side through the Trustpilot API (needs API credentials, which are not available in this repo).

- **Home page test failures on `main`** (`test/nuxt/home-page.test.ts`, `test/nuxt/showcase-carousel.test.ts`): found while running the full nuxt test project on a fresh branch off `main`, unrelated to the change being made there. `home-page.test.ts` expects `document.title` to be `'Anime Merchandise Webshop | AnimeNL'` with a meta description, but `app/pages/index.vue:3` only sets `title: 'Home'` and no description — the page never got `useSeoMeta`. `showcase-carousel.test.ts` expects the carousel image to have class `h-80`, but `app/components/showcaseCarousel.vue:23` uses `h-100` — a test/implementation mismatch, not obviously wrong on either side without knowing the intended layout. _Unverified_ which side (test or component) is the one that should change.

## Fixed

- **Navbar links to pages that do not exist** (`app/components/navbar.vue`): only `/products`, `/products/tcg`, `/search`, `/product/[id]` and `/support` existed; the TCG/Figures/Plush/Keychains sub-links gave a 404. Added the missing parent and sub-category pages (`app/pages/products/**`), all built on a shared `CategoryPage` component and `useCategoryProducts` composable that resolve a Medusa category by handle. Since Medusa had no subcategories for Singles/Packs/Boosters, Prize/Scale/Noodle Figures or Acrylic/Metal keychains, `medusa/src/scripts/seed.ts` now creates them (as children of the existing top-level categories) and assigns the matching seed products to them. _The seed change is verified against Medusa's `CreateProductCategoryDTO` types but not run end-to-end (no local Postgres/Medusa in this environment) — reseed the dev database to pick it up._
- **Most icons loaded from the Iconify API at runtime** (`app/components/navbar.vue`): only `lucide` and `flat-color-icons` were installed locally. Installed the `@iconify-json/*` packages for `mdi`, `game-icons`, `material-symbols`, `material-symbols-light`, `simple-icons`, `pinhead` and `at-icons`. `pinhead` and `at-icons` are not in Nuxt Icon's built-in list of recognized collection names, so its `local` auto-discovery silently skipped them; `nuxt.config.ts` now lists every collection explicitly in `icon.serverBundle.collections` so all nine are actually bundled server-side. Fixing this also surfaced two icon names that do not exist in `mdi` (`search`, `prize`); replaced with `magnify` and `trophy`. The navbar's icon list moved to `app/utils/navigation.ts`, with a test that checks every icon against its installed collection.
- **Medusa module debug logging was always on** (`nuxt.config.ts`, `medusa.debug: true`): now `!isProductionEnv(process.env.NODE_ENV)` (`shared/utils/env.ts`).
- **Secrets are baked into the build** (`nuxt.config.ts`): `runtimeConfig` reads `process.env` at build time, so changing `SMTP_PASS` or `MEDUSA_PUBLISHABLE_KEY` needs a rebuild. This is inherent to reading them via `process.env` in `nuxt.config.ts`; Nuxt already supports overriding any `runtimeConfig` key at runtime (no rebuild) via a `NUXT_`-prefixed environment variable, so no code change was needed. Documented in the README's new "Rotating a secret without a rebuild" section.
- **No rate limit on `POST /api/support`** (`server/api/support.post.ts`): added a per-IP in-memory rate limiter (`server/utils/rateLimit.ts`, 5 requests per 10 minutes, keyed by `x-forwarded-for`).
- **Support page copy needed a check by the shop owner**: confirmed with the shop owner and updated `shared/utils/support.ts` and `app/pages/support/index.vue` — shipping is 2 to 3 business days from when the order is placed; returns require the item to be unused and in its original packaging, and the customer pays for return shipping. Also updated in `AGENTS.md`.
- **Product cards never showed a price** (`app/components/productCarousel.vue`, `app/pages/products/tcg/index.vue`, `app/pages/search/index.vue`): these requested `variants.prices.*` (or nothing) without a `region_id`, but `productCard` reads `variants[0].calculated_price`. Now requesting `*variants.calculated_price` with a `region_id` resolved via the new `useDefaultRegionId` composable (search page already had a region id, just the wrong field).
- **Backorderable items in stock were capped at the stock quantity** (`app/pages/product/[id]/index.vue`, the `stock` computed): a backorderable variant now has no maximum quantity even while stock remains, matching a fully out-of-stock backorderable variant.
- **Test debt**: added tests for `server/api/{categories,collections,products,regions}.ts`, `app/pages/{index,products}` (`search` already had tests), and the components `productCard`, `productPageHeader` and `showcaseCarousel`.
- **Product page images were not centered vertically and/or zoomed correctly** (`app/pages/product/[id]/index.vue`): the `<img>` only had a `max-height`, so `object-contain` had no fixed box to center or scale within. Switched to a fixed `h-160 w-full object-contain object-center`.

- **"By series" links in the navbar did not work** (`app/components/navbar.vue`, `app/pages/search/index.vue`): the links passed a category _handle_ (`?category=tcg`) but the search page used it as a category _id_, so nothing was selected. The search page now accepts an id or a handle, and the links (`bySeriesLink`) also focus the Collection dropdown so the visitor picks the series. The Plush link used the handle `plushies`, which does not exist in the seed data; it is now `plush`. Handles in production must match `tcg`, `figures`, `plush` and `keychains`.
- **`bun run typecheck` failed with circular type errors** in `server/utils/medusa.ts` and every API route that uses it. Fixed by typing `medusaFetch` and the routes with `@medusajs/types`.
- **Support form let line breaks through into the email body** (`normalizeSupportRequest`). Fixed by collapsing line breaks in every field except the message.
